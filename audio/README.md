# Аудио: локальная проверка

Откройте терминал в `C:\code\ser017.github.io-master` и выполните `npm start`.
Раздел музыки: http://localhost:8080/audio/ (если порт занят, смотрите адрес в терминале).
`npm run test:audio` проверяет очередь, паузу, переходы, ошибки и предзагрузку.
`npm run build` проверяет сборку всего сайта. Эти команды не публикуют сайт.

## Что изменено

- Один постоянный аудиоэлемент для всех треков. Следующий запускается непосредственно по окончании предыдущего; переход не зависит от таймеров или видимости вкладки.
- Управление через Media Session: название и обложка трека, пауза, следующий/предыдущий трек, перемотка.
- Прямые ссылки Dropbox сокращают число перенаправлений. Воспроизведение начинается по мере загрузки; при ошибке прямой ссылки плеер пробует исходную.
- После начала звучания готовится запас из пяти следующих треков, не более двух загрузок одновременно. Готовые файлы сохраняются в Cache Storage браузера и используются после обновления страницы. При переходах и перестановках сохранённый запас не сбрасывается.
- Предел одного кешируемого файла — 192 МиБ, общий дисковый кеш — до 512 МиБ и 12 записей с хранением до семи дней. Старые файлы удаляются автоматически. Объекты готовых файлов ограничены суммарно 256 МиБ. Если хранилище недоступно, для небольших файлов действует резерв в памяти до 32 МиБ на файл.
- При заполнении хранилища уже сохранённые файлы остаются доступными, а новые небольшие треки готовятся в памяти. Если загрузка из запаса заканчивается во время сбоя перехода, плеер сразу использует готовый файл. Перед повторной сетевой попыткой кеш проверяется заново.
- Загрузка в кеш обрабатывается потоком; частичные ответы и обрезанные файлы не становятся готовыми треками. Таймаут одной попытки — 180 секунд, без получения данных — 20 секунд. После временных ошибок резерв повторно пополняется каждые 30 секунд, пока воспроизведение продолжается.
- Громкость находится в верхнем плеере. На узком экране нажмите значок динамика в шапке. Настройка сохраняется в этом браузере.
- Перемешивание не пропускает начало очереди и не снимает паузу. Повтор зацикливает один текущий трек.
- Поиск сохраняется при смене плейлиста. Поздний ответ предыдущего плейлиста не подменяет текущий список. Ошибки загрузки имеют кнопку повтора.
- Нижние пять кнопок помещаются на узких экранах. Пробел на кнопке выполняет действие этой кнопки.

## Проверка на Pixel 8 Pro / Chrome

1. Откройте локальную версию с телефона, используя адрес компьютера в домашней сети и порт сервера. Компьютер и телефон должны быть в одной сети.
2. Включите первый трек короткого плейлиста и выключите экран. Дождитесь окончания трека: должен начаться следующий. Повторите переход два-три раза.
3. Проверьте паузу и переключение с экрана блокировки, затем громкость на странице и возвращение в браузер.
4. Если возникает остановка, запишите название трека, состояние кнопки плеера после разблокировки и видимую ошибку.

Настоящая блокировка экрана проверяется на телефоне: изменение ширины окна компьютера её не имитирует. Android и Chrome могут ограничивать фоновые страницы, а скорость Dropbox зависит от сети. Предзагрузка уменьшает паузу, когда успевает завершиться; бесшовное воспроизведение без единого промежутка не гарантируется.

## Файлы

- `index.html`, `style.css`, `player.css` — разметка и оформление.
- `js/app.mjs` — интерфейс, громкость, поиск и Media Session.
- `js/player.mjs`, `js/queue.mjs`, `js/prefetch.mjs`, `js/reserve.mjs`, `js/audio-cache.mjs` — воспроизведение, очередь, запас треков и кеш файлов.
- `js/catalog.mjs`, `js/playlists-page.mjs` — каталог и страница плейлистов.
- `tests/player.test.mjs` — автоматические проверки.

Существующие файлы списков треков и обложки используются без изменения формата. Новые модули и стили включены в обычную сборку и будущую публикацию. Во время этой доработки отправка на GitHub не выполнялась.

## Восстановление после фоновых ошибок

- После исчерпания адресов текущего файла плеер делает до восьми повторных попыток с увеличивающимися задержками 1, 3, 7, 15, 30, 60, 60 и 60 секунд, не меняя трек и позицию очереди. При ошибке посередине песни позиция восстанавливается после получения метаданных.
- Ручная пауза и выбор другого трека отменяют ожидающий повтор. Запрет автозапуска (`NotAllowedError`) требует нажатия пользователем и записывается отдельно.
- При сбое появляется «Скачать отчёт». Кнопка остаётся доступной после успешного ручного повтора до обновления страницы. Также её можно показать параметром `?audio-debug=1`.
- Последние 240 событий хранятся локально в браузере под ключом `ser017-audio-diagnostics-v1`. Отчёт содержит версию плеера, время, состояние видимости/сети, идентификатор трека, коды ошибок и результат предзагрузки; ссылки Dropbox и параметры доступа в него не записываются. Автоматической отправки отчётов нет.
- После публикации обновите страницу на телефоне. Проверьте 3–5 переходов с выключенным экраном, отдельно ручную паузу во время повторной загрузки. При новой остановке скачайте отчёт до обновления страницы.
- Настольный браузер и автоматические тесты проверяют обработку ошибок, но не подтверждают работу на настоящем телефоне с заблокированным экраном. Во время полной приостановки страницы таймеры повторов также могут быть отложены браузером.

## Проверка запаса треков

На странице показано «Загружено вперёд: N из 5». Для контрольного опыта дождитесь полного запаса, выключите экран и проверьте несколько переходов. При смене очереди запас корректируется, готовые подходящие файлы сохраняются. Это не полная офлайн-загрузка всей библиотеки: браузер может удалить кеш при нехватке места, а музыка за пределами подготовленного запаса потребует сети.

Зависшие загрузки автоматически перезапускаются по отсутствию прогресса. События восстановления соединения и возврата на страницу ускоряют ожидающий повтор, если пользователь не ставил плеер на паузу. Статус сети `navigator.onLine` используется только в отчёте и не запрещает запросы.
