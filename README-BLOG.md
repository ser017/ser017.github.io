# Как писать и публиковать статьи

Рабочая папка: `C:\code\ser017.github.io-master`.
Старая папка `C:\code\site` сохранена как исходная копия; дальше работайте в новой папке.

## Посмотреть сайт на компьютере

```powershell
cd C:\code\ser017.github.io-master
npm.cmd start
```

Откройте http://localhost:8080/blog/ в браузере. «Обо мне»: http://localhost:8080/me/.
Новая статья: http://localhost:8080/blog/China-2026/.
Сохраняйте изменения в редакторе — сборка и страница обновляются автоматически.
Остановка просмотра: Ctrl+C в PowerShell. Используйте `npm.cmd`, если PowerShell запрещает запуск npm.ps1.
На другом компьютере сначала установите Node.js и Git, затем выполните `npm.cmd ci`.

## Написать статью

Статьи находятся в `_blog/posts/`, фотографии — в `_blog/assets/images/`.
Например, создайте `_blog/posts/My-trip.md`:

```markdown
---
title: "Моё путешествие"
date: 2026-10-27
tags: ["Путешествия"]
cover: "/assets/images/my-trip.jpg"
hero: true
author: "Ser017"
---

Текст статьи.

## Подзаголовок

![Подпись фотографии](/assets/images/my-trip.jpg)
```

Адрес статьи: `/blog/My-trip/`. Регистр букв важен на GitHub Pages.
`cover` можно убрать. `hero: false` скрывает большую обложку внутри статьи.
`listed: false` скрывает карточку из ленты, но страница остаётся доступной по прямой ссылке.
Это не защита от публикации: незаконченные статьи храните вне `_blog/posts/`, если не хотите выкладывать их.
При удалении статьи удалите также её старую собранную папку в `blog/`: сборка сохраняет старые страницы и тесты.

## Подготовить сайт и отправить на GitHub

После локальной проверки выполните (локальный просмотр можно оставить открытым):

```powershell
npm.cmd run build
git diff --stat
npm.cmd run publish -- "Добавил статью о Китае"
```

`build` обновляет готовые `blog/` и `me/`. `publish` повторяет сборку, сохраняет исходники и результат в Git и отправляет их в подключённую ветку GitHub.
Если новых изменений нет, команда повторяет отправку ранее созданного коммита.
Изменения других разделов этой командой не добавляются в коммит. Для них используйте обычные команды Git отдельно.
Если GitHub попросит авторизацию, войдите своим аккаунтом. При ошибке отправки файлы сохраняются на компьютере.
Сайт обновится после успешного завершения GitHub Pages; отправка в Git сама по себе ещё не подтверждает завершение Pages.

## Страница «Обо мне»

Редактируйте `_blog/posts/me.md`. В начале уже указано `permalink: /me/index.html`.
Сборка сразу создаёт `me/index.html`; вручную переносить страницу больше не нужно.
Старый `/blog/cv/` перенаправляет на `/me/`.
`me.md` — основной исходник страницы «Обо мне». Старый адрес `/blog/cv/` сохранён только для перенаправления.

## Что хранится в папках

- `_blog/` — редактируемые исходники блога, шаблоны, изображения и стили.
- `blog/`, `me/` — готовые страницы, создаваемые сборкой.
- `_site/` — временная копия для локального просмотра; `_build/` — отдельная временная сборка для публикации. Обе папки не отправляются в Git.
- `audio/`, `store/`, `404/` и остальные прежние разделы — существующие статические страницы.

Исходники и готовые страницы сохраняются в одном репозитории: публикация GitHub Pages из ветки продолжает работать без новой настройки Actions.

## Превью другой статьи внутри текста

Вставьте отдельной строкой, оставив пустые строки до и после:

```njk
{% articlePreview "/blog/howtochina/", "Короткое описание статьи." %}
```

Заголовок, обложка и ссылка берутся из выбранной статьи автоматически. Описание можно не указывать:

```njk
{% articlePreview "/blog/China-2026/" %}
```

Размеры компактной карточки задаются классом `article-preview` в `_blog/assets/css/main.css`.
